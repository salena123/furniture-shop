# Frontend Маэстро

Frontend сделан на React и собирается через Create React App. Маршрутизация работает через hash в адресе, поэтому отдельный сервер роутинга для разработки не нужен.

## Запуск и проверки

```powershell
cd frontend
npm install
npm start
```

Проверки перед передачей проекта:

```powershell
npm test -- --watchAll=false --runInBand
npm run build
npm run format:check
```

`REACT_APP_API_URL` задаёт адрес FastAPI. Шаблон находится в [.env.example](.env.example).

## Организация стилей

Все стили подключаются один раз в [src/styles/index.css](src/styles/index.css). Файлы импортируются в порядке каскада:

- `base.css` — переменные, шапка, кнопки, каркас и базовые элементы;
- `common.css` — общие карточки, формы, меню и диалоги;
- `public-pages.css` — каталог, проект и публичные страницы;
- `staff.css` — кабинет сотрудников и админские таблицы;
- `responsive.css` — мобильные и широкие варианты;
- `home.css` — карусель и секции главной страницы;
- `product-images.css` — фотографии товаров, галерея и предпросмотр в админке.

В JSX нет встроенных `style={{ ... }}`: размеры, цвета и кадрирование изображений настраиваются в CSS.

## Фотографии

Пять фотографий карусели лежат в `public/carusel/` и подключаются путями `/carusel/1.png` … `/carusel/5.png` в `src/config/slides.js`.

Фотографии товаров загружаются в кабинете администратора. Компонент `ProductImage` показывает их в каталоге, галерее и редакторе; относительные адреса файлов дополняются адресом backend из `REACT_APP_API_URL`. Главная фотография идёт первой, остальные сортируются по полю «Порядок». Для отсутствующих или недоступных файлов выводится заглушка. Размеры и кадрирование задаются в `src/styles/product-images.css`.

## Структура кода

Авторизация сотрудников использует серверную `HttpOnly` cookie. Токен не хранится в `sessionStorage` и не читается JavaScript; изменяющие запросы получают CSRF-заголовок автоматически.

Страница «О нас» заполняется в кабинете администратора → «Страница “О нас”» (`#/staff/about`). `pages/admin/AboutEditorPage.js` управляет текстовыми блоками и фотографиями, `components/admin/AboutTextEditor.js` добавляет обозначения форматирования к выделенному тексту. Поддерживаются заголовки, жирный текст, курсив, списки и ссылки. В текстовом поле видны обозначения (`**жирный**`, `*курсив*`, `## Заголовок`), в предпросмотре — итоговый вид. Редактор и публичная страница используют общий безопасный React-компонент `AboutContent`; произвольный HTML не исполняется. Стили находятся в `styles/about.css`.

Блоки можно переставлять, убирать и возвращать последний удалённый блок. Фотографии загружаются сразу, но содержание сайта меняется только после «Сохранить и опубликовать». До публикации правки хранятся только в открытом редакторе, при уходе со страницы теряются. JPG, PNG и WebP — до 10 МБ. Удаление блока убирает фото со страницы после публикации, но не удаляет файл с диска; неиспользуемые файлы автоматически не очищаются.

Страница «О нас» заполняется в кабинете администратора → «Страница “О нас”» (`#/staff/about`). `pages/admin/AboutEditorPage.js` управляет текстовыми блоками и фотографиями, `components/admin/AboutTextEditor.js` добавляет обозначения форматирования к выделенному тексту. Контакты редактируются администратором в разделе «Контакты сайта» и хранятся в таблице `site_contacts`. API: `GET /api/site/contacts` доступен посетителям, `PUT /api/site/contacts` — только администратору. Пустые поля показывают заглушки. Старые `REACT_APP_CONTACT_*` из `.env` используются только до первого сохранения в кабинете; после этого изменение контактов не требует пересборки frontend.

Товар редактируется одной кнопкой «Изменить» в `ProductEditor`: «Основное», «Характеристики», «Фотографии». Каждый раздел сохраняется отдельно; переключение сохраняет черновик полей. Новый товар сначала создаётся, затем в том же окне добавляются фото и характеристики.

`utils/productDetails.js` объединяет основные поля и дополнительные характеристики в таблице товара и предпросмотре администратора. Одинаковые значения не повторяются; несколько материалов и цветов выводятся одной строкой. Основной материал по-прежнему используется в фильтре каталога. Сохранённые данные при объединении отображения не удаляются.

- `components/` — переиспользуемые визуальные блоки;
- `pages/` — содержимое отдельных маршрутов;
- `layouts/` — общий каркас и кабинет;
- `hooks/` — загрузка ресурсов и действия с API;
- `context/` — авторизация сотрудника;
- `config/` — тексты и описания полей;
- `services/` — сетевой слой;
- `utils/` — чистые вспомогательные функции.

Форматирование выполняется командой `npm run format`. Настройки находятся в [.prettierrc.json](.prettierrc.json).
