# Маэстро — концепция интерфейса, 22.09.2026

Основа: просмотренный упрощённый макет пользователя в Figma. Сайт mebelmaestro.ru указан пользователем как референс, но при открытии показал проверку доступа; она не проходилась. Документ описывает проектируемый интерфейс; наличие готового frontend из него не следует. Возможности backend сверены с `README.md` и `docs/api-contract.md`. Роли сотрудников — только **менеджер** и **администратор**. Имена, фотографии работ, даты и счётчики в визуальных макетах демонстрационные. Результат — четыре PNG-концепции, сгенерированные встроенным ImageGen, не файл Figma с редактируемыми слоями.

## Визуальная система

Сохранить узнаваемую композицию: белая компактная шапка «Маэстро», зелёные «О нас» и «Контакты», бордовая кнопка «Войти», большая карусель с фотографией бордовой кухни и подписью. Основной зелёный — `#16734D`, бордовый — `#A52C36`, фон — `#F6F7F4`, текст — `#202622`, поверхности — белые. Шрифт — Manrope с системным sans-serif в качестве запасного.

Улучшения: общий контейнер шириной до 1280 px, предсказуемые отступы 8/16/24/32/48 px, крупные интерьерные фотографии, ограниченное количество акцентов. Заголовки страниц 32–40 px, основной текст 16 px; в кабинетах допускается 14 px для плотных таблиц. Скругления 10–16 px, тонкие границы, минимум теней. Зелёный обозначает основные действия, бордовый сохраняет характер исходного макета; статусы всегда подписаны текстом.

## 1. Главная

**Шапка:** логотип слева; рядом компактное меню категорий; справа «О нас», «Контакты», «Войти». Без корзины, избранного и регистрации покупателей.

**Карусель:** широкая фотография интерьера, спокойное затемнение под текстом, короткая подпись, кнопка «Оставить заявку». Стрелки и индикатор текущего слайда видимы постоянно. Под фотографией — три подписанные вкладки для переключения слайдов. Предлагается ручное переключение; автопрокрутка не обязательна.

**Ниже:** только компактный подвал с навигацией; дополнительных рекламных блоков нет. «О нас» и «Контакты» ведут на отдельные страницы или компактные панели, которые не входят в текущие четыре изображения. Фотографии и тексты — согласуемый контент. Редактирование карусели из кабинета не заявлено в API и является отдельной проектируемой возможностью, если понадобится.

**Переходы:** категория → каталог; стрелки и подписанные вкладки → другой слайд; «Оставить заявку» → форма заявки; «О нас»/«Контакты» → соответствующая страница или панель; «Войти» → форма входа сотрудника → кабинет по роли.

## 2. Каталог категорий и выполненных работ

Хлебные крошки, заголовок выбранной категории и компактный перечень подкатегорий. На широком экране навигация слева, справа сетка из двух колонок карточек. Карточка содержит фотографию, название и краткие характеристики. Основной объект backend — товар (`product`); в публичном дизайне он представлен как работа из портфолио. Отдельная сущность «проект» не требуется.

Поиск по названию и фильтр материала поддержаны API. В PNG показаны компактные фильтры; фильтр стиля и сортировка «Сначала новые» — проектируемые элементы, их поддержку необходимо проверить или добавить при реализации. Показывать только активные категории и работы. Для пустой подкатегории — понятное сообщение и ссылка на родительскую категорию.

**Переходы:** категория → подкатегория → карточка работы. Проектируемая карточка работы включает галерею, описание, материал, характеристики и кнопку «Обсудить похожую мебель». Кнопка открывает форму заявки без регистрации: имя, телефон, город, удобное время связи, комментарий, при необходимости размеры/замер и согласие на обработку данных. Конкретный состав обязательных полей следует согласовать со схемой запроса. После отправки — подтверждение; публичная отправка заявки уже поддержана backend.

## 3. Заявки менеджера

Светлый рабочий экран в общей палитре. Слева компактная навигация «Заявки»; внизу имя сотрудника, роль и выход. Вверху заголовок, поиск, фильтры **«Все», «Мои», «Без ответственного»**, выбор статуса. Основная таблица: заявка/работа, клиент, телефон, город, ответственный, статус. Счётчики возможны на основе существующей статистики; их значения в изображениях — примеры, состав метрик проверяется при реализации.

Клик по строке открывает проектируемую боковую панель: контактные данные, работа и материал, размеры/замер, пожелания клиента, ответственный, статус, комментарии и история событий. На телефоне это отдельный экран. Основное действие свободной заявки — **«Взять в работу»**; интерфейс выполняет поддержанные операции назначения и, при необходимости, смены статуса без предположения об автоматической смене на сервере.

Реальные статусы API: `new` — «Новая»; `in_progress` — «В работе»; `contacted` — «Связались»; `measurement_scheduled` — «Назначен замер»; `quote_prepared` — «Расчёт подготовлен»; `completed` — «Завершена»; `cancelled` — «Отменена». Это варианты ручной смены статуса, а не обязательная линейная последовательность.

Менеджер может назначать заявку только на себя или снимать себя. Редактирует и удаляет только собственные комментарии. Не показывать ему управление каталогом и пользователями. Личный календарь, уведомления, задачи и загрузка файлов в заявки — дополнительные проектируемые возможности, не часть подтверждённого объёма.

## 4. Управление каталогом администратора

То же оформление кабинета. Навигация: «Заявки», **«Каталог»**, «Сотрудники»; внутри каталога — «Работы», «Категории», «Материалы», «Характеристики». Администратор также работает с заявками и назначает любого доступного сотрудника.

Главный вид каталога: поиск, фильтр категории, активные/скрытые записи, кнопка «Добавить работу». Строка содержит миниатюру, название, категорию, материал и состояние видимости. Редактор работы: основные данные, категория, материал, характеристики, фотографии и выбор главного изображения. Форма управления категориями показывает связь «категория → подкатегория».

Действие для снятия работы с публикации назвать **«Скрыть с сайта»**: API сохраняет запись и историю заявок. Отдельные статусы «Черновик» и «На проверке» не предусмотрены. Категорию с вложенными категориями или товарами нельзя удалить — интерфейс объясняет причину. Управление сотрудниками поддержано API, но его отдельный экран не входит в эти четыре макета.

## Адаптивность и состояния

На планшете каталог — две колонки; на телефоне — одна, категории открываются компактным списком. Шапка сворачивается в меню, подпись карусели остаётся читаемой. Таблицы кабинетов превращаются в карточки с теми же основными действиями. Элементы управления доступны клавиатурой, имеют видимый фокус и удобную область нажатия.

Для каждого экрана при реализации предусмотреть загрузку, пустой результат, ошибку с повтором и сохранённое состояние. Ошибки формы показывать рядом с полями. Истечение авторизации возвращает к входу. Разграничение прав обеспечивается backend; скрытие кнопок лишь отражает эти права в интерфейсе.
